### 备案与合规（这版新增，容易漏）

- [ ] 确认 Cloudflare **橙云代理未开启**（开了等于放弃备案换来的速度）

### nginx / 传输
- [ ] 三个子域证书有效，`certbot renew --dry-run` 已验证自动续期
- [ ] HTTP 强制 301 跳 HTTPS；HSTS 已开
- [ ] L1 / L2 加 `X-Robots-Tag: noindex`、`Cache-Control: private, no-store`
- [ ] `.htpasswd-lab` 权限 640，属主 `root:www-data`
- [ ] `server_tokens off`
- [ ] 安全组只放行 22 / 80 / 443；**8000 和 3306 都不对外**

### MySQL（多项目共用，隔离必做）
- [ ] `journal` 独立 schema，**不与其他项目混表**
- [ ] 应用连接用 `journal_app`（仅 `SELECT/INSERT/UPDATE/DELETE`），**不是 root、不是 DDL 用户**
- [ ] 用户限定 `@'127.0.0.1'`；`bind-address = 127.0.0.1`
- [ ] `innodb_buffer_pool_size` 显式设为 512M（不让它按内存自动放大）
- [ ] **已开 2G swap**，`vm.swappiness=10` —— 防 OOM killer 静默杀掉 MySQL 拖垮所有项目
- [ ] `performance_schema` 的取舍已决定（关掉省内存 / 缩小保留观测能力）
- [ ] 连接池设了 `pool_recycle=3600` + `pool_pre_ping=True`（防 `MySQL server has gone away`）

### API 鉴权
- [ ] `/api/entries` GET **按 session 角色过滤**，访客 session 拿不到 `private` 密文
- [ ] 写接口查 `credentials.can_write`，不只校验"已登录"
- [ ] session cookie：`HttpOnly` + `Secure` + `SameSite=Lax`
- [ ] WebAuthn RP ID = `journal.yourdomain.com`，origin 严格校验
- [ ] 访客口令接口有失败限流（nginx `limit_req` 或应用层）
- [ ] 访客口令用 Argon2id 哈希存储，不是明文、不是 MD5

### 加密
- [ ] Argon2id 参数 m≥64MB、t≥3；若降级 PBKDF2-SHA256 则迭代 ≥600k
- [ ] 每次加密独立随机 12 字节 IV，**禁止复用**（GCM 下 IV 复用是灾难性的）
- [ ] `verifier` 密文可区分"口令错"与"数据损坏"
- [ ] KEK / DEK 只存内存，不落 `localStorage` / `sessionStorage`
- [ ] 草稿自动保存走加密路径
- [ ] 前端逐条验签，失败时显式告警
- [ ] 恢复码已生成并**离线物理保存**

### 运维
- [ ] 备份用 `mysqldump --single-transaction`（InnoDB 一致性快照，不锁表）
- [ ] 备份定期拉到本地或对象存储，异地留一份，**并做过一次真实恢复演练**
- [ ] 数据库口令存 systemd `EnvironmentFile`（权限 600），**不进 git、不写死在代码里**
- [ ] FastAPI 以**非 root** 用户运行（systemd `User=`）
- [ ] sitemap / RSS / Pagefind 索引只含 L0
- [ ] L0 图片已压缩（WebP/AVIF）——带宽是 2C4G 上唯一真实的瓶颈

## 4. 版本变更记录

这份文档改了三版，原因值得记下来——**每次都是因为一个基础事实被澄清，而不是因为设计想法变了**：

| 版本 | 当时的假设 | 得出的架构 |
|---|---|---|
| v1.0 | 服务器可换到境外 | Next.js + 香港 VPS + Docker + Cloudflare Tunnel/Access |
| v1.1 | 服务器不能换、**未备案** | 弃用服务器，整站托管 Cloudflare Pages ×3 |
| v2.0 | 已备案 + 大陆 2C4G 实例 | 一台服务器 + nginx + FastAPI + SQLite，完全不用 Cloudflare |
| **v2.1** | **MySQL 已为其他项目常驻** | **同上，数据库换成共用的 MySQL 实例（独立 schema + 独立用户）** |

前两版的复杂度全部来自"如何绕开没有备案"。**备案已完成 → 问题不存在 → 架构回到最简单的形态**，而且顺带回到了你最熟的技术栈。

教训：**动手设计之前先把部署约束问清楚。** 服务器在哪、备案状态、带宽多少，这三个事实决定的东西比任何框架选型都多。
