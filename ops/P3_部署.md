## Step 1 · 部署后端到服务器

```bash

```

### systemd 配置

```bash
# 1. 创建运行用户（非 root）
sudo useradd -r -s /usr/sbin/nologin journal
# 2. 授权目录
sudo chown -R journal:journal /srv/blog/packages/journal/api
# 3. 安装 unit（改 User= 为 journal）
sudo sed -i 's/User=www-data/User=journal/; s/Group=www-data/Group=journal/' deploy/systemd/journal-api.service
sudo cp deploy/systemd/journal-api.service /etc/systemd/system/
# 4. 环境变量（0600）
sudo cp deploy/env/.env.example /srv/blog/deploy/env/.env.journal
sudo chmod 600 /srv/blog/deploy/env/.env.journal
# 编辑填入：JOURNAL_DB_PASSWORD / SESSION_SECRET
sudo systemctl daemon-reload
sudo systemctl enable --now journal-api
```

### RP_ID / Origin（重要）

`.env.journal` 里必须：
```
RP_ID=journal.leyanwc.xyz
ORIGIN=https://journal.leyanwc.xyz
```

## Step 3 · 首次初始化（浏览器）

1. 打开 `https://journal.leyanwc.xyz`
2. 出现「首次设置」向导：
   - **注册主人 Passkey**（Windows Hello / Touch ID，can_write=1）
   - **设置主口令 + 读口令**（≥8 位）
   - **生成恢复码 → 抄写到纸上**（必须！丢失 = 内容永久丢失）
3. 完成 → 进入空日记列表

验证点：
- `journal` 库的 `credentials` 表出现 1 行，`can_write=1`
- `crypto_params` 表 2 行（owner/reader），含 salt/params/verifier
- `signing_keys` 表 1 行
- `key_escrow` 表 1 行（wrapped_kek + wrapped_sk 非空）

---

## Step 4 · 写日记 + 访问控制验证

1. 写一篇 **private** 日记 → 保存
2. 检查 MySQL：`entries` 表一行，`ciphertext`/`dek_owner` 为密文（BLOB），`visibility='private'`，`dek_reader` 为 NULL
3. 再写一篇 **shared** → `dek_reader` 非 NULL
4. **访客登录**（另一个浏览器 / 隐身窗口）：
   - 输读口令 → 只能看到 shared 那条，private 不在列表
   - 点共享条目 → 能解密看内容
5. **访客不能写**：没有「新日记」按钮（前端隐藏）+ 直接 POST `/api/entries` 返回 403（后端强制）

---

## Step 5 · 手机 passkey 只读验证（⑥ P3 顺序 7）

1. `journal.leyanwc.xyz` 手机打开 → 注册一个新 passkey（此时 credentials 表非空，走普通注册 → `can_write=0`）
2. 手机上登录 → 能看到全部条目 → 点「新日记」→ 无写权限（前端隐藏）
3. 直接 curl 模拟写：
   ```bash
   curl -X POST https://journal.leyanwc.xyz/api/entries \
     -H 'Content-Type: application/json' \
     -b 'session=...' \
     -d '{"id":"...", ...}'    # 应 403
   ```
4. 服务端日志/`credentials` 表确认 `can_write=0`

## Step 6 · 备份与恢复演练

```bash
# MySQL 一致性备份（③ 校验：InnoDB 不锁表）
mysqldump --single-transaction -ujournal_app -p journal > /backup/journal-$(date +%F).sql
# 定期回传本地/对象存储；每周做一次恢复演练
mysql -ujournal_ddl -p journal < /backup/journal-latest.sql
```

> 明文内容**永远不存在于数据库**。恢复 = 只恢复密文 + 你的口令/恢复码仍在手。
> 若丢失恢复码 = 数据不可恢复（E2EE 的必然代价，⑤ §5）。

## Step 7 · 清理与维护

```bash
# 过期 session/challenge（挂 cron，与备份同一入口）
cat > /etc/cron.daily/journal-cleanup <<'EOF'
#!/bin/bash
mysql -ujournal_app -p"$PASS" journal -e "DELETE FROM sessions WHERE expires_at < NOW(); DELETE FROM webauthn_challenges WHERE expires_at < NOW();"
EOF
chmod +x /etc/cron.daily/journal-cleanup
```

## 读口令轮换（⑤ §7 + ⑩ key_epoch 语义）

半年一次或访客变动时。流程（客户端驱动，重包封套用 `reader_epoch`）：

1. 新读口令 → 前端派生新 `KEK_reader'`
2. 逐条解 `dek_reader`（旧 KEK）→ 重包（新 KEK）→ `reader_epoch += 1`（一次一批 50 条，可中断续跑）
3. `crypto_params.reader.key_epoch += 1`；同时更新 `password_hash`（服务端登录校验）
4. 换 `/api/session` 用的读口令

## 检查清单（对应 ⑥ §1）

- [ ] `/api/entries` GET 访客只见 shared（服务端过滤）
- [ ] 写接口查 `credentials.can_write`（不只"已登录"）
- [ ] session cookie：`__Host-sid` + HttpOnly + Secure + SameSite=Lax
- [ ] WebAuthn RP_ID = journal.leyanwc.xyz，origin 严格校验
- [ ] `/api/session` 有 nginx limit_req（5r/m）；`/api/auth/recover` 5r/h（⑩）
- [ ] 读口令存 Argon2id 哈希（非明文）
- [ ] Argon2id 参数 owner m≥64MB / reader m≥32MB（⑪ Q5）
- [ ] 每次加密独立随机 IV；`key_escrow` 已托管（恢复码 + 私钥）
- [ ] 前端逐条验签，失败红色告警
- [ ] 恢复码已离线保存
- [ ] CPU/内存：uvicorn 1 worker，200MB 上下；swap 2G 兜底
